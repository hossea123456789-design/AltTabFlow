# AltTabFlow 1.1.4 — 이번 갱신 내용

기준: 2026-11-10. 비교 기준은 마지막 이전 배포 1.1.2다. 이번 작업 중 1.1.3에 발생한 전경 표시 회귀까지 보완한 최종본이 1.1.4다.

## 1. 사용자 요청과 확인된 문제

- 실제 프로그램 창을 마우스로 클릭한 뒤에는 **그 창을 기준으로 직전 프로그램과 왕복**해야 한다. 선택 목록에서 마우스를 올리기만 하는 동작을 추가한 요청이 아니다.
- P4 도구모음의 메인 창과 같은 프로세스의 항상 위 폴더 팝업이 함께 열려 있었다. 현재 foreground HWND와 목록에 캐시된 대표 HWND가 달라질 수 있어, 기존 완전 일치 방식은 현재 프로그램을 못 찾고 같은 P4를 다시 선택할 수 있었다.
- 활성화 요청 반환을 실제 전환 완료로 간주하고 선택 창을 먼저 숨기는 경로가 있었다. 실패한 대상을 최근 사용 기록에 먼저 넣는 처리도 제거했다.
- 1.1.3에서 지연을 줄이려 입력 스레드 연결을 제거했으나, 이 PC에서는 백그라운드 전환기의 전경 권한 확보가 실패했다. 프로세스·훅 생존과 실제 호출 성공은 달랐다. 1.1.3을 정상 최종본으로 사용하지 않는다.

## 2. 최종 수정

1. **실제 클릭 기준**: 전용 이벤트 스레드에서 foreground를 기록하고 Alt+Tab 시작 때 현재 창을 직접 재확인한다. 지연 이벤트가 새 클릭 기록을 덮지 못하도록 발생 시각을 비교한다.
2. **P4 팝업과 메인 창 구분 오류**: 실제 소유 루트와 PID를 함께 사용한다. 팝업이 캐시에 있고 메인을 클릭한 경우, 그 반대 경우 모두 현재 앱으로 판단한다. 소유 관계 없는 같은 프로세스의 독립 창은 합치지 않는다.
3. **전환 작업 분리**: WindowActivation이 한 번에 하나의 백그라운드 작업으로 실제 활성화를 요청한다. 전경 권한 확보에 필요한 호환 처리는 작업 스레드에서 수행하고, AltTabFlow의 UI 스레드를 외부 앱의 입력 큐에 연결하지 않는다. 외부 응답은 먼저 20ms 제한으로 확인한다.
4. **전환 완료 확인**: 실제 foreground가 대상이 된 뒤 선택 화면을 닫는다. 다른 외부 앱을 클릭하면 그 선택을 존중한다. 확인·재시도 한도는 250ms이며, 정상 전환에 매번 붙는 대기 시간이 아니다.
5. **빠른 입력**: 이미 완료된 일반 Alt+Tab 제스처는 화면·FX 생성 없이 동일한 선택 규칙으로 바로 전환한다. 반복 입력 순서를 유지하고, 방향키·고정 상세 모드는 기존 상세 화면을 사용한다.
6. **FX 우선순위**: 16ms 예약 한 개로 연속 대상 변경을 합쳐 입력 처리가 효과 렌더링 뒤에서 기다리지 않도록 한다. 아우라, 딤드, 색상 연동, 실제 창 미리 표시를 유지한다.
7. **진단 보강**: 이벤트에 PID를 남기고 `releaseToSwitchMs`와 `requestToSwitchMs`를 분리한다. `inputMs`에는 사용자가 Alt를 잡고 있던 시간도 포함된다. 테스트용 가짜 창은 실제 사용 로그에 남기지 않는다.

개인 설정, 관리자 권한 게임 호환, 주 모니터 표시, 앱 숨기기, 상단 등록과 이름순 정렬, Enter 묶음 진입, Backspace 복귀, 자동 실행 선택을 유지했다. 설정 파일 변경 전후 해시가 동일하다.
