# AltTabFlow 1.1.6 — UI 개선 갱신 내용

기준일: 2026-11-10. 비교 기준: 마지막 배포 1.1.5.

## 1. 개선 결과

사용자가 보여준 색상·효과 설정 화면에서 작은 기본 탭, 흰색 콤보박스, 어두운 본문, 사각 버튼과 밝은 제목 표시줄이 섞여 있었다. 설정 화면을 **왼쪽 메뉴 + 오른쪽 카드 + 하단 고정 저장 영역**으로 다시 구성했다. 모든 색상은 기존 7개 프리셋을 그대로 사용하며 저장된 사용자 선택을 보존한다.

- 작은 상단 탭 → 넓은 왼쪽 메뉴. 현재 위치를 강조색 테두리·배경·페이지 제목으로 표시.
- 색상 이름 드롭다운 → 실제 색상 점이 있는 7개 버튼과 즉시 미리보기.
- 기본 사각 버튼 → 공통 둥근 버튼, hover·pressed·선택·키보드 포커스 상태 구분.
- 기본 체크박스 → 20px 체크 + 제목/설명, 행 전체 클릭 영역.
- 흰색 기본 보기·크기 콤보박스 → 테마 선택 필드와 테마 메뉴, 방향키 선택 유지.
- 저장/취소 → 하단 고정, 저장 버튼만 강조색 채움. 화면 높이가 부족하면 본문만 스크롤.
- 상단 정렬 → 테마 체크 목록과 수동 등록 카드. 실행하지 않은 등록 앱 유지.
- Windows 제목 표시줄·우클릭 메뉴 → 선택 프리셋의 색으로 통일.
- 메인 창 → 보기 선택을 하나의 묶음으로 정리, 켜짐 체크, F2/Esc 안내, 실제 hover·클릭 상태.
- 마우스 버튼 → 누를 때 실행하지 않고 같은 영역에서 놓을 때 실행. 밖으로 옮겨 놓으면 취소.

**동작 유지:** 마지막 키를 놓으면 하이라이트 창으로 전환, Chrome 묶음 대표 창 선택, Enter/Backspace, 직전 앱 왕복, 실제 창 클릭 기준, P4 전환 처리, 주 모니터·숨김·정렬·자동 실행·FX·관리자 권한 게임 호환을 유지한다. 이번 버전에서는 KeyboardHook/ShortcutRouter/MRU/WindowActivation/FX 구현을 변경하지 않았다.

## 2. 디자인·구현 명세

사용자가 지적한 문제는 어두운 본문과 흰색 Windows 기본 탭·콤보박스, 작은 사각 버튼, 밝은 제목 표시줄이 서로 어울리지 않는 것이었다. 색만 덮는 방식 대신 **왼쪽 메뉴 / 오른쪽 설정 카드 / 하단 고정 저장 영역**으로 구성한다. 기존 기능과 Preferences 키는 모두 보존한다.

96 DPI 기준 client 860×792, 맑은 고딕 본문 10pt, 설명 9pt, 페이지 제목 16pt bold, 상단 ‘설정’ 21pt bold. FormBorderStyle.FixedDialog, AutoScaleMode.Dpi, TopMost를 유지한다. 제목 표시줄은 UiPaint.TitleBar에서 DWM의 dark mode(20), caption color(35), text color(36)를 적용한다. 지원하지 않는 Windows에서는 시스템 기본 프레임을 사용하고 설정 기능은 계속 동작한다. 표준 닫기·이동 기능은 보존한다.

창 높이가 WorkingArea보다 크면 높이를 줄인다. 본문 패널만 스크롤되며 저장·취소는 화면 하단에 남는다. 96 DPI 기본 크기와 높이 600 축소를 자동 렌더링 검사했다. 모든 혼합 DPI·화면 조합을 실측했다고 해석하지 않는다.

**공통 컴포넌트: UiControls.cs**

- FlowButton은 표준 Button을 상속하고 GDI로 그린다. 저장(primary), 선택(selected), 일반, 조용한 보조(quiet) 상태를 분리한다. 반경 9, 키보드 포커스 점선, hover/pressed 채색을 사용한다. 색상 버튼은 실제 Accent 점과 선택 체크를 표시한다.
- FlowCheck는 표준 CheckBox를 상속한다. 네이티브 checked·Space·Tab·접근성 동작은 유지하고 20px 체크와 제목/설명을 그린다. 행 전체가 클릭 영역이다.
- FlowSelect는 흰색 ComboBox 대신 테마 버튼과 ContextMenuStrip을 사용한다. 표시 폭과 드롭다운 최소 폭을 맞추고 선택 체크를 그린다. 좌우/위아래 키로 값 변경, 클릭/Space로 메뉴 열기. 메뉴는 소유 컨트롤 수명 동안 유지하고 Closed에서 Dispose하지 않는다.
- FlowAppList는 owner-draw ListBox와 체크 집합이다. 클릭/Space 등록·해제, 위아래 키 선택, 선택 앱 체크 상태를 접근성 객체에도 노출한다. 실행하지 않은 기존 등록 앱을 유지한다.
- FlowCard는 카드 배경·테두리만 그리는 이중 버퍼 Panel이다. TextBox는 IME·선택·편집을 위해 네이티브 컨트롤을 유지하고 borderless로 카드 안에 배치한다.
- FlowMenuRenderer는 설정 드롭다운과 전환 목록 우클릭 메뉴에 같은 배경·강조색·체크·글자색을 적용한다.

Tab/Shift+Tab으로 컨트롤 이동, Space로 체크, Ctrl+Tab/Ctrl+Shift+Tab으로 설정 메뉴 순환, Esc 취소를 지원한다. Enter는 기본 저장 동작이며 수동 앱 이름 입력칸에서는 앱 등록으로 소비한다. 색상 미리보기만 누르고 취소하면 원본 prefs와 설정 파일은 변경하지 않는다. 저장할 때만 ApplyValues와 기존 자동 실행 설정을 적용한다.

설정이 열린 동안 일반 Alt+Tab 가로채기를 억제하고 configuring 상태에서 전환 명령을 무시한다. 저장 후 보기·레이아웃·테마·숨김·정렬을 함께 반영한다. 설정을 닫고 전환 화면으로 돌아오면 명시적인 상세 모드를 유지한다.

메인 전환 화면도 같은 버튼 규칙을 사용한다. 세 보기 버튼을 공통 배경에 묶고, 앱 묶기/미리보기는 켜짐 체크를 표시한다. 설정 F2·닫기 Esc는 조용한 보조 버튼, 오른쪽 창 전환 버튼은 Accent 채움이다. hover는 실제 선택을 바꾸지 않는다. 마우스 누름에서 바로 실행하지 않고 같은 영역에서 놓을 때 실행하며, 영역 밖에서 놓으면 취소한다. hover가 바뀔 때 해당 영역만 무효화하고 전역 애니메이션 타이머를 추가하지 않는다.

참조: [Microsoft DWMWINDOWATTRIBUTE 공식 문서](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute). 실제 UI 구현·좌표·검사 결과의 1차 근거는 부록 소스다.

실제 Windows 창에서 로즈 설정 화면·기본 동작·상단 정렬·제목 표시줄을 확인했다. 자동 렌더링으로 7종 색상과 세 가지 전환 보기를 확인했다. 현재 실측 DPI는 96이며 모든 혼합 DPI/화면 조합을 확인한 것은 아니다. 실제 P4·Chrome에서의 물리 키 반복 전환은 기존 자동 회귀 검사와 별도다.

UI는 기존 WinForms/GDI 위에 구현했다. 새 웹 런타임·이미지 엔진·애니메이션 타이머를 넣지 않았고, 메인 창 hover는 달라진 영역만 다시 그린다. 전체 전환 시간의 개선 수치를 새로 측정했다고 주장하지 않는다.
