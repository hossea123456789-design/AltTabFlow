# AltTabFlow 1.1.5 — 이번 갱신 내용

기준: 2026-11-10. 비교 기준: 1.1.4. 이번 사용자 요청이 과거의 “화살표 조작 시 선택 화면 고정” 요구사항보다 우선한다.

## 1. 최종 동작

**일반 Alt+Tab → 방향키로 이동 → 누른 키를 모두 놓으면 현재 하이라이트 창으로 전환하고 선택 화면을 닫는다.** AltTabFlow 자체는 백그라운드에서 계속 실행된다.

| 조작 | 결과 |
| :--- | :--- |
| Alt를 누른 채 Tab 반복 | 선택만 이동한다. |
| Alt+Tab 이후 화살표로 이동 | 고정 모드로 바뀌지 않고 계속 탐색한다. |
| 화살표를 놓았지만 Alt를 누르고 있음 | 화면을 유지한다. |
| Alt를 먼저 놓았지만 화살표 또는 Tab을 누르고 있음 | 마지막 키를 놓을 때까지 화면을 유지한다. 화살표 반복 입력도 유지한다. |
| 마지막 키를 놓음 | 현재 하이라이트 창으로 한 번 전환하고 선택 화면을 닫는다. |
| Chrome 창 여러 개가 묶인 항목에서 모두 놓음 | 그 묶음의 첫 번째 대표 창, 즉 제목·미리보기에 표시된 창으로 전환한다. |
| Enter로 Chrome 묶음을 펼치고 개별 창 선택 후 모두 놓음 | 펼친 목록에서 하이라이트된 개별 창으로 전환한다. |
| Esc | 취소한다. 이후 남은 키를 놓아도 다시 확정하지 않는다. |

일반 탐색에서 Enter 묶음 진입, Backspace 복귀, Home/End, PageUp/PageDown도 화면을 강제로 고정하지 않는다. Ctrl·Shift를 함께 누르고 있으면 해당 키까지 모두 놓을 때 확정한다. Ctrl+Alt+Space 또는 Ctrl+Alt+Tab으로 명시적으로 연 고정 상세 화면과 검색·설정·항목 메뉴 등 명시적인 고정 조작은 기존 동작을 유지한다.

## 2. 구현 변경

- `KeyboardHook.cs`: ShortcutRouter가 현재 눌린 키를 집합으로 추적한다. 일반 세션에서 모든 키가 해제된 마지막 key-up만 Commit을 보낸다. 키 반복 입력을 중복으로 세지 않으며, 시작 전에 누르고 있던 방향키와 좌우 Alt·Ctrl·Shift도 고려한다. 현재 키의 비동기 상태는 이전 이벤트 상태일 수 있으므로 현재 down/up과 반대쪽 수정키 상태로 판단한다.
- `Program.cs`: Commit을 NavigationReleased로 전달하고 Escape Cancel을 취소 경로로 전달한다. 기존 회귀 검사를 최신 계약으로 수정하고 30개 검사를 추가했다.
- `SwitcherForm.cs`: 일반 방향키·묶음·페이지 탐색에서 persistent를 강제로 켜는 처리를 제거했다. 일반 세션의 NavigationReleased에서 기존 Choose 경로로 확정한다. 화면 안내를 “키를 모두 놓으면 전환”으로 바꿨다.
- `SettingsForm.cs`, `사용법.txt`: 마지막 키 해제와 Chrome 대표 창 동작을 안내한다.
- `AltTabFlow.csproj`: 버전 1.1.5.

키보드 훅에 대기·폴링·파일 읽기를 추가하지 않았다. 마지막 키-up에서 명령을 보내는 방식이다. 실제 전경 확인, P4 소유 팝업 처리, MRU 왕복, FX, 관리자 권한 게임 호환, 주 모니터, 정렬·숨김·색상·자동 실행 설정은 기존 경로를 유지한다.
