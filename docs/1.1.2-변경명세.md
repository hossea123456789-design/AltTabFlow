# AltTabFlow 1.1.2 — 이번 MD 갱신 내용

작성 기준: 2026-11-10. 기존 1.1.1 완전 명세에 추가·교체할 **1.1.2 변경분만** 모은 문서다. 기존 기능 설명과 변경되지 않은 전체 소스·아이콘은 반복하지 않는다.

## 1. 우클릭 메뉴 오류로 실행이 종료되던 문제 수정

발생 오류:

```text
Cannot access a disposed object.
Object name: 'System.Windows.Forms.ContextMenuStrip'.
```

프로그램이 삭제된 것이 아니라 실행 중 종료된 문제다. 기존 오류창의 ‘AltTabFlow를 시작하지 못했습니다’는 실행 중 예외를 잘못 분류한 문구였다.

원래 코드는 항목 우클릭 메뉴를 매번 생성하고, `Closed` 이벤트 안에서 즉시 `menu.Dispose()`를 호출했다. Windows Forms는 Closed 이벤트가 끝난 뒤에도 같은 메뉴 HWND의 부모를 복원한다. 이미 해제된 메뉴에 접근하면서 예외가 발생했다.

실제 오류 경로:

```text
ModalMenuFilter.ProcessMouseButtonPressed
→ CloseActiveDropDown
→ ContextMenuStrip.SetVisibleCore
→ ToolStripDropDown.SetVisibleCore
→ SetWindowLong
→ Control.CreateHandle
→ ObjectDisposedException
```

`MenuTests`에서 실제 SwitcherForm의 메뉴를 띄우고 테스트 폼을 향한 외부 클릭 메시지를 `Application.FilterMessage`에 전달해, 수정 전 **동일한 예외와 호출 경로를 재현**했다. 전역 키보드·마우스 입력을 주입하거나 사용자 프로그램을 조작하지 않는다.

### 수정 후 반드시 지킬 메뉴 수명 규칙

1. SwitcherForm이 `readonly ContextMenuStrip itemMenu` 한 개를 소유하고 재사용한다.
2. `Closed`에서는 configuring 상태와 단축키 억제만 해제한다. 메뉴나 폼을 Dispose하지 않는다.
3. 다시 열 때 기존 메뉴가 보이면 Close를 완료한 뒤 이전 ToolStripItem만 정리하고 새 항목을 구성한다. Closed 이벤트를 매번 중복 등록하지 않는다.
4. 프로그램 종료 시 `itemMenu.Close()`가 반환된 다음 `itemMenu.Dispose()`를 실행한다. Shutdown에는 중복 실행 방지 조건을 둔다.
5. 예외를 무조건 삼키는 방식으로 숨기지 않는다. 실제 메뉴 종료 경로의 오류가 없어야 한다.

## 2. 시작 실패와 실행 중 오류 구분

| 발생 시점 | 로그 이름 | 사용자 안내 |
| :--- | :--- | :--- |
| 초기화 중 실패 | startup-error | AltTabFlow를 시작하지 못했습니다. |
| 초기화 완료 후 Application.Run 중 실패 | runtime-error | AltTabFlow 실행 중 오류가 발생해 종료되었습니다. |

Program.Main의 `running` 상태로 두 경우를 구분한다. 이번 우클릭 메뉴 오류는 실행 중 오류에 해당한다.

`MenuTests.cs`와 `--menu-self-test`를 추가했다. 정상 프로그램 초기화보다 먼저 실행·종료하므로 개인 설정과 로그인 자동 실행 등록을 바꾸지 않는다.

## 5. 잠금 화면 때문에 실제 창 검사가 실패한 경우의 처리

실제 창 표시 검사 중 Windows 잠금 화면의 `LockApp`이 테스트 좌표를 가린 사례를 확인했다. 이는 메뉴 수정으로 실제 창 표시가 깨졌다는 증거가 아니다.

`PeekTests`의 결과에 `environment`를 추가해 단계별 예상 HWND·실제 HWND·실제 프로세스·클래스·예상 창 표시 상태를 기록한다. LockApp이 가리고 있으면 검사를 통과로 바꾸지 않고 잠금 해제 후 같은 검사를 다시 수행한다. 이번에는 잠금 해제 후 실제 창 검사 10개가 모두 통과했다.
