> **업데이트/배포:** 기존 저장소 `hossea123456789-design/AltTabFlow` 자체가 Public인 경우 같은 저장소의 공개 Releases에서 익명으로 버전과 SHA-256을 확인하고 앱 버튼으로 교체합니다. 별도의 `AltTabFlow-Downloads` 저장소나 배포 PAT는 불필요합니다. **저장소 Public 및 [v1.1.12 공개 릴리스 게시 완료](https://github.com/hossea123456789-design/AltTabFlow/releases/tag/v1.1.12).**

> **검증 분리:** 첨부된 1.1.8 인계 명세는 기본 206 + UI 71 + Peek 10 + 메뉴 7 + Focus 18(이미 포함된 Peek 10 중복) = **고유 302개 검사 통과**를 보고합니다. GitHub CI에서는 현재 기본 206개+UI 85개+업데이터 22개+관리자 자동 시작 11개(총 324개)를 별도 검증하며, 실제 전경·메뉴·게임 회귀 검사는 구분합니다.

## 메이플스토리 전체화면(Alt+Enter)과 창 전환

Alt+Enter로 확장된 메이플스토리가 최대화 또는 전체화면 상태로 전경을 점유할 경우, AltTabFlow는 다른 TopMost 창보다 더 위에 선택 UI를 표시하도록 Windows HWND_TOPMOST Z-order를 재확인합니다. 원래 게임이 다시 foreground가 되더라도 곧바로 전환기를 닫지 않으며, 다른 앱 선택 시 실제 foreground 활성화를 최대 900ms까지 확인한 후 정리합니다. 미리보기 Z-order 복원은 활성화 확인 뒤로 미룹니다.

**제한:** 진정한 DXGI 독점 전체화면, 게임 보호/안티치트 입력 제한 및 Windows 포커스 정책은 임의 오버레이의 우선순위로 강제할 수 없습니다. 가능하면 게임의 **전체화면 창(테두리 없는 창)** 모드를 사용해 실기기에서 비교하십시오. 게임 창을 강제로 최소화하거나 영구 TopMost 상태를 변경하지 않습니다.

## 공개 저장소 1개로 원클릭 업데이트 (1.1.12)

설정 → 업데이트 확인으로 **같은 공개 GitHub 저장소**의 Releases에서 새로운 Windows EXE를 받습니다. 사용자 GitHub 로그인/PAT는 요구하지 않습니다. 자동 배포는 성공한 Windows CI와 같은 `main` SHA의 실행 파일만 사용하고, `GITHUB_TOKEN`으로 공개 프리릴리스를 생성합니다. 앱은 업로드된 ZIP의 SHA-256과 EXE 버전을 검증하고 재시작합니다.

**최초 공개 전환 절차(현재 완료):** GitHub 관리 권한 보유자가 저장소 Settings → General → Danger Zone → Change repository visibility → Public을 한 번 승인해야 합니다. 자동 배포 워크플로는 Private 상태에서 릴리스를 만들지 않으며, Public으로 전환하면 GitHub의 `public` 이벤트가 배포 작업을 자동 실행합니다. 별도 Actions 수동 실행은 필요하지 않습니다. 저장소 공개는 과거 커밋·이슈·로그까지 공개될 수 있어 사전 점검이 필요합니다.

## 주요 기능

- 앱별 묶음 목록, 카드, 아이콘 전환 (Ctrl+1/2/3)
- MRU 기반 직전 프로그램 선택과 Alt 유지 중 Tab·방향키 탐색, 마지막 키 해제 시 전환
- 실제 대상 창을 일시적으로 앞으로 보여 주는 Peek, 순환 아우라와 주변 딤드
- 주 모니터 중심 배치, 다중 모니터 대상 선택, 7개 테마
- 앱 상단 등록, 숨기기, 검색, 로그인 자동 시작 설정 저장
- 메이플스토리처럼 관리자 권한으로 실행된 앱을 위한 `Game-compat-mode.cmd`
- 1.1.2: 우클릭 메뉴 수명 관리 오류 수정, `--menu-self-test` 추가
- 1.1.10: 로그인 시 관리자 자동 실행(작업 스케줄러·Program Files 보호 폴더), 업데이트 독립 창·취소, 마우스 휠 이동 후 마지막 키 해제 Commit
- 1.1.9: 게임 호환 관리자 권한으로 안전하게 재시작(UAC/기존 인스턴스 인계), EXE에서 GitHub 업데이트 확인·자동 다운로드·백업 후 교체·재시작
- 1.1.8: 일반 Alt+Tab 종료 누락 복구 — 오래된 키 눌림 기록 정리, 세션 중 누락된 key-up 확인, 일반 재시작 시 이전 고정 모드 초기화
- 1.1.7: 숨길 앱 Enter 줄바꿈, Ctrl+Alt+Tab 고정 화면 유지·반복/역방향/늦은 Ctrl 승격, 상단 정렬 앱 아이콘 및 비동기 로딩
- 1.1.6: 설정 화면을 왼쪽 메뉴/오른쪽 카드/하단 고정 저장으로 전면 개편. 테마형 버튼·체크·선택 필드·우클릭 메뉴·제목 표시줄 적용, 마우스 up 확정 및 이탈 취소
- 1.1.5: Alt+Tab 이후 방향키로 이동해도 고정하지 않으며 누른 키를 모두 놓았을 때 현재 하이라이트 창으로 확정. Esc는 취소하고 명시적 상세 모드는 유지
- 1.1.4: 실제 클릭한 창·P4 소유 팝업 MRU 왕복, 전경 전환 완료 확인, 비동기 활성화 및 입력 최적화

## v1.1.10: 로그인 시 관리자 자동 실행과 개선된 업데이트 창

- 설정 → 기본 동작 → **Windows 시작 시 자동 실행**과 **로그인 시 관리자 권한으로 자동 시작**을 함께 체크하고 저장합니다.
- 최초 1회 UAC 승인 후 AltTabFlow를 **관리자 보호 경로 `%ProgramFiles%\AltTabFlow\AltTabFlow.exe`**에 복사하고 Task Scheduler에 **현재 사용자 로그온 + Interactive token + Highest run level** 작업으로 등록합니다. 다음 Windows 로그인부터 UAC 반복 승인 없이 관리자 권한으로 시작합니다. 일반 Run 레지스트리 시작은 동시에 사용하지 않습니다.
- 관리자 자동 시작을 해제하면 등록 작업을 제거하고 일반 시작 옵션에 따라 Run 등록으로 되돌립니다. UAC를 취소하면 기존 옵션을 유지합니다.
- 업데이트 확인은 **항상 보이는 별도 업데이트 창**에서 버전 조회·진행 상태·취소를 표시합니다. 1.1.12부터는 같은 Public 저장소에서 토큰 없이 업데이트하므로 인증 입력칸이 없습니다.
- **마우스 휠**: 일반 Alt+Tab에서 선택만 이동합니다. Alt/Tab/방향키 등의 마지막 key-up에 휠로 마지막 선택한 창을 한 번 전환합니다. 고정 Ctrl+Alt+Tab에서는 휠 조작 후에도 고정 화면을 유지합니다.
- GitHub CI는 예약 작업 등록의 권한/실제 로그인 동작 및 공개 릴리스 기반 업데이트·게임 입력을 대체 검증하지 못합니다. 사용자 Windows 실기기 확인이 필요합니다.

## 실행 / 게임 호환 / 자동 업데이트

**메이플스토리처럼 관리자 권한으로 실행한 게임에서는 AltTabFlow도 관리자 권한이 필요할 수 있습니다.** 기존 일반 실행본이 남아 있으면 새 관리자 실행본이 무시되는 현상을 수정했습니다.

1. 오른쪽 아래 트레이의 AltTabFlow 아이콘을 우클릭해 **게임 호환: 관리자 권한으로 다시 시작**을 누르거나, 설정의 **기본 동작** 아래쪽에서 같은 버튼을 누릅니다.
2. Windows UAC 요청에 동의하면 기존 프로그램이 정상 종료되고 관리자 모드가 실행됩니다. 취소하면 원래 실행본을 유지합니다.
3. 프로그램이 여전히 Windows Alt+Tab을 표시하면 설정의 **Alt+Tab 전환 사용**, 일시 중지 상태 및 관리자 여부를 확인합니다. 게임·후킹 실기기 검사는 별도 진행해야 합니다.

**자동 업데이트(1.1.12 이상):** 트레이의 **업데이트 확인** 또는 설정의 **업데이트 확인 · 자동 설치**를 누르면 `AltTabFlow` 공개 저장소의 Releases에서 인증 없이 최신 버전을 조회합니다. SHA-256 무결성과 EXE 버전을 검증하고 자동 교체·재시작합니다. 1.1.11 및 이전 클라이언트는 다른 업데이트 경로를 사용하므로, **첫 1.1.12 설치 한 번은 공개 Release ZIP을 직접 받아야 합니다.** 이후 업데이트에는 수동 압축 해제가 필요하지 않습니다.

**주의:** 업데이트 대상은 실사용 검증 완료 정식 릴리스가 아니라 CI를 통과한 **실행 후보**입니다. 관리자 게임 검증을 의미하지 않습니다. 현재 업데이트 경로로 전환하는 **1.1.12 최초 설치 한 번**만 수동 다운로드가 필요하며, 이후부터는 프로그램 내부 버튼으로 갱신합니다. 기존 설치 경로가 쓰기 제한된 폴더이면 UAC가 추가로 필요할 수 있습니다.

## 실행·빌드

Windows에서 `Windows-Build.cmd`를 실행합니다. .NET 8 SDK가 없으면 설치 여부를 묻고, 소스에서 `package.ps1`을 호출합니다. 성공하면 `releases/AltTabFlow-latest-win-x64.zip`을 생성합니다. 완성 EXE를 이 저장소의 소스 코드와 혼동하지 마세요.

기존 SDK로 직접 빌드하려면:

```powershell
dotnet restore .\AltTabFlow.csproj
dotnet build .\AltTabFlow.csproj -c Release
```

검증은 **로그인한 Windows 사용자 세션에서 잠금을 해제한 상태**로 실행합니다.

```powershell
$exe = '.\bin\Release\net8.0-windows\AltTabFlow.exe'
& $exe --peek-self-test
& $exe --menu-self-test
& $exe --focus-self-test
& $exe --ui-self-test
```

다섯 검사 모두 종료 코드 0 및 `%LOCALAPPDATA%\AltTabFlow\*-test.json`의 `failures=0`을 확인해야 합니다. `--peek-self-test`는 테스트 창을 표시할 수 있습니다. 자동 배포용 `package.ps1`은 검사 실패 시 최신 배포 ZIP을 갱신하지 않습니다.

## GitHub 관리 원칙

1. 버그 수정 및 기능 제안은 **Issues**로 기록합니다.
2. 변경 코드는 별도 브랜치에서 수정하고 **Pull Request**로 `main`에 병합합니다.
3. GitHub Actions는 **컴파일/게시 가능 여부만 확인**합니다. 실제 창, 메뉴, 게임 모드는 로컬 Windows에서 별도 검증해야 합니다.
4. 입력/UI/업데이터/시작 계획 324개 GitHub CI가 성공해야 자동 Preview Release를 만들며, 실제 게임·UAC/온라인 교체 검증 완료와 구분합니다.
5. 상태 파일이나 창 제목이 포함된 로그는 저장소에 커밋하지 않습니다. 오류 보고 시에도 민감한 창 제목과 경로를 삭제합니다.

자세한 변경 이력은 [CHANGELOG.md](CHANGELOG.md), 인수 점검은 [docs/ROADMAP.md](docs/ROADMAP.md), 1.1.8 변경 근거는 [docs/specs/AltTabFlow_1.1.8_갱신내용.md](docs/specs/AltTabFlow_1.1.8_갱신내용.md)를 확인합니다.

**배포 주의:** CI에서 생성한 후보 EXE는 실사용 창 제어 검사 전까지 검증 완료 릴리스로 배포하지 않습니다. 이 프로그램은 Windows 시스템 파일을 수정하지 않으며 정상 종료하면 원래 Alt+Tab이 돌아옵니다.
